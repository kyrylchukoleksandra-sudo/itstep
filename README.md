# Заняття 10. Бази даних. Робота з базою даних SQLite у Python

Будь-яка серйозна програма працює з даними, які мають зберігатися навіть після її перезапуску або вимкнення комп'ютера (наприклад, прогрес гравця, список користувачів, історія покупок чи каталог товарів). Зберігати великі обсяги інформації у звичайних текстових файлах або змінних незручно, повільно й небезпечно, тому в розробці використовують **бази даних**.

---

## 1. Поняття бази даних та СУБД

**База даних (БД, Database)** — це організована за певними правилами сукупність взаємопов'язаних даних, призначена для тривалого зберігання, швидкого пошуку, аналізу та оновлення інформації.

**СУБД (Система управління базами даних, DBMS)** — це комплекс програмного забезпечення, який виступає посередником між програмою (або користувачем) і самими даними. СУБД відповідає за створення структури БД, швидкий пошук, перевірку типів даних, безпеку та одночасний доступ (приклади: *SQLite, PostgreSQL, MySQL, Oracle, MongoDB*).

### Чому не звичайні текстові файли (`.txt` / `.csv`)?
1. **Швидкість пошуку:** щоб знайти один рядок у текстовому файлі на 1 мільйон записів, програмі доведеться прочитати весь файл. БД використовує спеціальні структури (індекси), знаходячи запис за мілісекунди.
2. **Цілісність і типи даних:** у `.txt` можна випадково записати текст замість числа. База даних суворо контролює формат кожного поля.
3. **Безпека та транзакції:** якщо під час запису у файл вимкнеться світло, файл може пошкодитися. СУБД гарантує, що зміна або відбудеться повністю, або не відбудеться взагалі.
4. **Зв'язки між даними:** БД дозволяє легко пов'язувати різні сутності (наприклад, «Учень» ↔ «Курс» ↔ «Викладач») без дублювання зайвої інформації.

### Класифікація баз даних

| Критерій порівняння | Реляційні БД (SQL) | Нереляційні БД (NoSQL) |
| :--- | :--- | :--- |
| **Модель зберігання** | Таблиці зі стовпцями (**полями**) та рядками (**записами**). | Документи (JSON/BSON), пари «ключ — значення», графи або колонки. |
| **Схема даних** | Фіксована (жорстка): перед записом даних потрібно заздалегідь визначити всі стовпці та їхні типи. | Гнучка (динамічна): різні записи в одній колекції можуть мати різний набір полів. |
| **Зв'язки** | Будуються через ключі (`PRIMARY KEY`, `FOREIGN KEY`) та об'єднання таблиць (`JOIN`). | Дані часто зберігаються вкладеними об'єктами всередині одного документа. |
| **Мова запитів** | Єдина стандартизована мова **SQL**. | Кожна СУБД має власний синтаксис запитів. |
| **Приклади СУБД** | SQLite, PostgreSQL, MySQL, MariaDB, MS SQL Server. | MongoDB, Redis, Cassandra, Neo4j. |

## 2. Вбудована реляційна СУБД SQLite3

**SQLite3** — це компактна вбудована реляційна СУБД, модуль для роботи з якою вже входить до стандартної бібліотеки Python (`import sqlite3`).

### Особливості архітектури SQLite
На відміну від «великих» СУБД (як-от PostgreSQL чи MySQL), які працюють як окрема серверна програма у фоні, SQLite не має окремого сервера:
* Уся база даних зберігається в **одному звичайному файлі** на диску (зазвичай із розширенням `.db`, `.sqlite`, `.sqlite3` або `.sl3`).
* Бібліотека `sqlite3` у Python напряму читає та змінює цей файл.
* **Де застосовується:** мобільні додатки (Android та iOS використовують SQLite під капотом), браузери (зберігання історії та закладок), локальні десктопні програми, ігри, прототипи вебсайтів та тестування.
* **Обмеження:** оскільки це один файл на диску, SQLite не підходить для високонавантажених сайтів, де тисячі користувачів одночасно намагаються щось змінити в базі в одну секунду.

### Типи даних та обмеження в SQLite

| Тип даних у SQLite | Що зберігає | Аналог у Python | Приклад значення |
| :--- | :--- | :--- | :--- |
| **`INTEGER`** | Цілі числа (додатні, від'ємні, нуль) | `int` | `18`, `-5`, `2026` |
| **`REAL`** | Дробові числа (з плаваючою крапкою) | `float` | `19.99`, `3.14` |
| **`TEXT`** | Текстові рядки будь-якої довжини | `str` | `'Nick'`, `'Київ'` |
| **`BLOB`** | Сирі бінарні дані (картинки, аудіо, файли) | `bytes` | `b'\x89PNG...'` |
| **`NULL`** | Спеціальне значення «порожньо / невідомо» | `None` | `NULL` |

### Ключі та обмеження полів (Constraints)
* **`rowid`** — прихований системний стовпець, який SQLite автоматично створює для кожної таблиці. Він містить унікальний числовий номер кожного рядка (`1, 2, 3...`).
* **`PRIMARY KEY` (Первинний ключ)** — поле (найчастіше `id INTEGER PRIMARY KEY AUTOINCREMENT`), яке однозначно ідентифікує кожен запис у таблиці та не може повторюватися.
* **`FOREIGN KEY` (Зовнішній ключ)** — поле, яке посилається на `PRIMARY KEY` іншої таблиці, створюючи зв'язок між ними (наприклад, `category_id` у таблиці товарів посилається на `id` у таблиці категорій).
* **`NOT NULL`** — забороняє залишати поле порожнім при додаванні запису.
* **`UNIQUE`** — гарантує, що всі значення в цьому стовпці будуть унікальними (наприклад, логін або email).

## 3. Мова структурованих запитів SQL

**SQL (Structured Query Language)** — це декларативна мова програмування, призначена для створення структури баз даних та маніпулювання даними в реляційних СУБД. Описуючи SQL-запит, ми вказуємо **що** хочемо отримати, а СУБД сама визначає, **як** найшвидше це виконати.

> **Правило гарного тону:** ключові слова SQL (`SELECT`, `FROM`, `WHERE`, `INSERT`, `UPDATE`, `DELETE`) прийнято писати **ВЕЛИКИМИ ЛІТЕРАМИ**, а назви таблиць і стовпців — **малими**, щоб запит легко читався. Кожен запит завершується крапкою з комою `;`.

### Групи команд SQL

#### 1. DDL (Data Definition Language) — керування структурою таблиць
* **`CREATE TABLE назва_таблиці (поле1 ТИП, поле2 ТИП);`** — створює нову таблицю.
  * *Захист від помилки повторного створення:* `CREATE TABLE IF NOT EXISTS students (id INTEGER PRIMARY KEY, name TEXT, age INTEGER);` — створить таблицю лише тоді, коли її ще не існує.
* **`ALTER TABLE назва_таблиці ADD COLUMN нове_поле ТИП;`** — додає новий стовпець до вже існуючої таблиці.
* **`DROP TABLE назва_таблиці;`** — безповоротно видаляє таблицю разом з усіма її записами.

#### 2. DML (Data Manipulation Language) — робота з даними (CRUD)
Абревіатура **CRUD** описує 4 базові операції з даними в будь-якій програмі: **C**reate (створення), **R**ead (читання), **U**pdate (оновлення), **D**elete (видалення).

| Операція | Команда SQL | Синтаксис та пояснення |
| :--- | :--- | :--- |
| **Create** (Додавання) | `INSERT INTO` | `INSERT INTO students (name, age) VALUES ('Олена', 16);` — додає новий рядок у таблицю. Порядок значень у `VALUES` має збігатися з порядком стовпців у дужках. |
| **Read** (Вибірка) | `SELECT ... FROM` | `SELECT name, age FROM students;` — повертає вказані стовпці. Символ `*` (`SELECT * FROM students;`) вибирає **всі** стовпці таблиці. |
| **Update** (Оновлення) | `UPDATE ... SET` | `UPDATE students SET age = 17 WHERE name = 'Олена';` — змінює значення вказаних полів. **Увага:** без умови `WHERE` оновляться **всі** рядки в таблиці! |
| **Delete** (Видалення) | `DELETE FROM` | `DELETE FROM students WHERE rowid = 1;` — видаляє рядки, що відповідають умові. **Увага:** без умови `WHERE` таблиця буде повністю очищена! |

#### 3. Фільтрація, сортування та об'єднання даних
* **`WHERE` (Фільтрація):** відбирає записи за умовою. Підтримує оператори порівняння (`=`, `!=`, `>`, `<`, `>=`, `<=`), логічні оператори (`AND`, `OR`, `NOT`), перевірку діапазону (`BETWEEN 14 AND 18`) та пошук за шаблоном (`LIKE 'Ол%'`, де `%` означає будь-яку кількість символів).
* **`ORDER BY` (Сортування):** сортує результат за вказаним полем: `ORDER BY age ASC` (за зростанням, за замовчуванням) або `ORDER BY age DESC` (за спаданням).
* **`LIMIT` (Обмеження кількості):** обмежує кількість повернутих рядків (наприклад, `SELECT * FROM students ORDER BY age DESC LIMIT 3;` — топ-3 найстарших учнів).
* **Агрегатні функції:** дозволяють рахувати статистику прямо в запиті:
  * `COUNT(*)` — підраховує кількість рядків.
  * `SUM(поле)` — обчислює суму значень.
  * `AVG(поле)` — знаходить середнє арифметичне.
  * `MIN(поле)` / `MAX(поле)` — знаходить мінімальне та максимальне значення.
* **`JOIN` (Об'єднання таблиць):** дозволяє поєднати дані з двох пов'язаних таблиць в один результат за спільним ключем (наприклад, вивести ім'я учня з таблиці `Students` поруч із назвою його курсу з таблиці `Courses`).

## 4. Робота з `sqlite3` у Python: об'єкти та безпека

### Ключові об'єкти та методи
1. **`sqlite3.connect(database, timeout=5.0)`** — встановлює з'єднання з файлом БД і повертає об'єкт `Connection`. Якщо файл не існує, він створюється автоматично. Параметр `timeout` визначає, скільки секунд Python чекатиме на розблокування файлу, перш ніж викличе помилку `OperationalError: database is locked`.
2. **`connection.cursor()`** — створює об'єкт `Cursor`, який керує виконанням SQL-запитів та вказує на поточний рядок у результатах вибірки.
3. **`cursor.execute(sql, parameters)`** — виконує один SQL-запит.
4. **`cursor.executemany(sql, seq_of_parameters)`** — зручний метод для масового додавання одразу десятків чи сотень записів зі списку.
5. **`connection.commit()`** — фіксує **транзакцію** (усі виконані зміни зберігаються на диск). Без `commit()` зміни після `INSERT`, `UPDATE` або `DELETE` зникнуть після закриття програми.
6. **`connection.rollback()`** — скасовує всі незбережені зміни поточної транзакції, якщо під час виконання виникла помилка.
7. **`connection.close()`** — закриває з'єднання з файлом БД та звільняє ресурси операційної системи.

### Захист від SQL-ін'єкцій (Параметризовані запити)
Ніколи не варто підставляти змінні від користувача у SQL-запит через f-рядки (`f"SELECT * FROM users WHERE name = '{user_input}'"`). Якщо користувач введе спеціальні символи SQL, він може зламати запит або отримати доступ до чужих даних (це називається **SQL-ін'єкцією**).

Натомість у `sqlite3` використовують знаки питання `?` як заповнювачі, а значення передають у вигляді кортежу другим аргументом у `execute()`:
```python
cur.execute("INSERT INTO first_table (name) VALUES (?);", ("Nick",))

```

## 5. Візуальний перегляд БД у PyCharm (Database Navigator)

Оскільки файл `.sl3` / `.db` має бінарний формат, відкрити його у звичайному текстовому редакторі неможливо. Плагін **Database Navigator** дозволяє переглядати таблиці, стовпці та записи у зручному табличному вигляді прямо всередині PyCharm:

1. **Встановлення:** *Settings (шестірня) → Plugins → Marketplace → пошук `Database Navigator` → Install → Restart IDE*.
2. **Підключення файлу:** вкладка *DB Navigator → Database Browser → кнопка `+` → SQLite3 → у полі `Database files` обрати ваш `.sl3` файл → `Test Connection` → `OK*`.
3. **Навігація:** розгорніть гілку `Connection → Schemas → main → Tables` і двічі клацніть на потрібну таблицю (натисніть `No filter` для відображення всіх записів).
4. **Важливе правило блокування:** SQLite блокує файл на запис, коли до нього підключена інша програма. Якщо ви переглядаєте базу через плагін і хочете запустити Python-скрипт, який змінює дані, спочатку натисніть правою кнопкою миші на підключення у `DB Browser` і виберіть **Disconnect**.

## 6. Поняття ORM (Object-Relational Mapping)

У реальних промислових проєктах програмісти рідко пишуть «чистий» SQL вручну для кожної дрібної операції. Замість цього використовують **ORM (Object-Relational Mapping — об'єктно-реляційне відображення)**.

**ORM** — це підхід і спеціальні бібліотеки, які перетворюють таблиці реляційної бази даних на звичайні класи в ООП, а рядки таблиць — на об'єкти (екземпляри) цих класів.

### Як співвідносяться поняття БД та ООП у ORM:

| Концепція Бази Даних | Концепція ООП у Python |
| --- | --- |
| **Таблиця** (`Students`) | **Клас** (`class Student:`) |
| **Стовпець / Поле** (`name`, `age`) | **Атрибут класу** (`student.name`, `student.age`) |
| **Рядок / Запис у таблиці** | **Об'єкт / Екземпляр класу** (`s1 = Student("Nick", 15)`) |
| **SQL-запит** (`INSERT`, `SELECT`) | **Виклик методу Python** (`session.add(s1)`, `Student.query.all()`) |

### Переваги використання ORM:

1. **Єдиний стиль коду:** ви пишете весь проєкт на Python в об'єктно-орієнтованому стилі, не перемикаючись між Python і рядками SQL.
2. **Незалежність від СУБД:** якщо проєкт виріс із локальної `SQLite` до потужної `PostgreSQL`, достатньо змінити один рядок налаштувань підключення — переписувати запити в коді не доведеться.
3. **Вбудований захист:** ORM автоматично екранує всі дані, захищаючи програму від SQL-ін'єкцій.

*Найпопулярніші ORM у екосистемі Python:* **SQLAlchemy** (золотий стандарт для Flask/FastAPI та аналітики), **Django ORM** (вбудована у фреймворк Django), **Peewee**, **Tortoise ORM** (для асинхронних додатків).
