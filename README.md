# Фінальний проєкт. Пошукова система по збережених вебсайтах

Фінальний проєкт підсумовує весь курс та поєднує **об'єктно-орієнтоване програмування (ООП)**, **роботу з базою даних (`sqlite3`)**, **веб-парсинг (`requests` + `BeautifulSoup`)** і **графічний інтерфейс (`tkinter`)**. Ваша мета — створити повноцінний десктопний додаток, який зберігає перелік вебсайтів у базі даних, аналізує їхній текстовий вміст за запитом користувача та будує рейтинг релевантності сторінок.

---

## 1. Як працює програма (Загальний сценарій)

Уявіть спрощений аналог Google, який шукає інформацію не по всьому інтернету, а лише по тій базі сайтів, яку ви самі йому вказали:

1. **Керування базою джерел:** користувач через вікно програми додає посилання на сайти (наприклад, сторінки Вікіпедії, новинні портали, блоги). Посилання зберігаються у локальному файлі БД `.db` / `.sl3` і не зникають після закриття програми. За потреби базу можна переглянути або повністю очистити однією кнопкою.
2. **Пошуковий запит:** користувач вводить слово або фразу (наприклад, `"Python"` або `"штучний інтелект"`) і натискає кнопку пошуку.
3. **Обхід та аналіз сторінок:** програма дістає всі збережені URL із бази даних, по черзі завантажує HTML-код кожної сторінки, очищає його від тегів та службових скриптів і підраховує, скільки разів шукане слово зустрічається на кожному сайті.
4. **Ранжування результатів:** програма сортує сайти від найбільшої кількості збігів до найменшої та виводить результат на екран (наприклад: `1. https://uk.wikipedia.org/wiki/Python — знайдено 142 збіги`).

## 3. Архітектура проєкту та взаємодія модулів

Щоб програма була чистою, зрозумілою та отримала максимальні **40 балів за архітектуру**, її потрібно поділити на окремі файли (модулі) та класи за принципом **єдиної відповідальності**: кожен клас робить лише свою роботу і нічого не знає про внутрішню будову інших.

### Рекомендована структура файлів проєкту
```text
search_project/
├── database.py      # Клас DatabaseManager — робота тільки з SQLite
├── parser.py        # Клас WebParser — завантаження сторінок та підрахунок слів
├── ui.py            # Клас SearchAppUI — вікно, кнопки, поля введення та виведення
└── main.py          # Функція run() та точка входу if __name__ == "__main__":

```

### Схема взаємодії об'єктів у `main.py`

Клас інтерфейсу (`SearchAppUI`) не пише SQL-запитів і не завантажує сайти самостійно. Натомість під час створення він отримує готові екземпляри `db` та `parser` через конструктор `__init__` і просто викликає їхні методи при натисканні кнопок:

```python
from database import DatabaseManager
from parser import WebParser
from ui import SearchAppUI


def run():
    db = DatabaseManager("sites.db")
    parser = WebParser()
    app = SearchAppUI(db, parser)
    app.start()


if __name__ == "__main__":
    run()

```

## 4. Детальний розбір кожного модуля: що використовувати і як реалізувати

### Модуль 1: `database.py` — Робота з базою даних (`sqlite3`)

**Інструмент:** вбудований модуль Python `sqlite3` (встановлювати не потрібно).

**За що відповідає клас `DatabaseManager`:**
Зберігає шлях до файлу бази даних, створює таблицю при першому запуску та надає зручні методи для додавання, отримання і видалення посилань.

#### Що саме використати та як реалізувати:

1. **Конструктор `__init__(self, db_name="sites.db")`:**
* Зберігає ім'я файлу в атрибут `self.db_name = db_name`.
* Одразу викликає метод `self.create_table()`, щоб таблиця гарантовано існувала перед початком роботи.


2. **Створення таблиці (`create_table`):**
* Використовуйте запит:
```sql
CREATE TABLE IF NOT EXISTS sites (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    url TEXT UNIQUE NOT NULL
);

```


* Ключове слово **`UNIQUE`** не дозволить зберегти одне й те саме посилання двічі.


3. **Додавання сайту (`add_url(self, url)`):**
* Використовуйте параметризований запит `INSERT INTO sites (url) VALUES (?);`, передаючи `(url,)` другим аргументом у `execute()`.
* Огорніть запис у `try...except sqlite3.IntegrityError:` — якщо таке посилання вже є в базі, програма не впаде, а поверне `False` (або повідомлення про дублікат).
* Не забудьте про `connection.commit()`.


4. **Отримання всіх сайтів (`get_all_urls(self)`):**
* Виконайте `SELECT url FROM sites;`.
* Метод `cur.fetchall()` поверне список кортежів вигляду `[('https://site1.com',), ('https://site2.com',)]`. Зручно одразу перетворити його у звичайний список рядків через list comprehension: `[row[0] for row in rows]`.


5. **Очищення бази (`clear_database(self)`):**
* Виконайте `DELETE FROM sites;` та зафіксуйте зміни через `connection.commit()`.


6. **Зручне керування з'єднанням:**
* Використовуйте конструкцію `with sqlite3.connect(self.db_name) as conn:` — вона автоматично викликає `commit()` при успішному завершенні блоку, але для повного закриття файлу в кінці методу додавайте `conn.close()`.

### Модуль 2: `parser.py` — Парсинг сайтів (`requests` + `BeautifulSoup`)

**Інструменти:** бібліотеки `requests` (`pip install requests`) та `beautifulsoup4` (`pip install beautifulsoup4`).

**За що відповідає клас `WebParser`:**
Приймає посилання та шукане слово, завантажує вебсторінку, очищає її від розмітки та рахує кількість збігів.

#### Що саме використати та як реалізувати:

1. **Конструктор `__init__(self)`:**
* Задайте атрибут `self.headers = {"User-Agent": "Mozilla/5.0"}` — багато сайтів відхиляють запити без заголовка `User-Agent`, сприймаючи їх як спам-ботів.


2. **Завантаження та очищення сторінки (`get_page_text(self, url)`):**
* Виконайте `response = requests.get(url, headers=self.headers, timeout=5)` (параметр `timeout=5` захистить програму від вічного зависання, якщо сайт не відповідає).
* Перевірте `if response.status_code == 200:`.
* Створіть об'єкт `soup = BeautifulSoup(response.text, "html.parser")`.
* **Очищення від невидимого коду:** перед отриманням тексту видаліть теги `<script>` (JavaScript) та `<style>` (CSS), щоб шукане слово не рахувалося у службовому коді:
```python
for tag in soup(["script", "style"]):
    tag.decompose()

```


* Витягніть увесь видимий текст сторінки за допомогою **`soup.get_text(separator=" ")`**.
* Огорніть весь метод у `try...except requests.RequestException:` — якщо посилання бите, сайт не працює або немає інтернету, метод поверне порожній рядок `""` або `None`, а програма продовжить перевіряти інші сайти.


3. **Підрахунок збігів на одному сайті (`count_matches(self, url, query)`):**
* Отримайте чистий текст сторінки. Якщо текст отримати не вдалося, поверніть `None` (щоб можна було відрізнити «сайт недоступний» від «знайдено 0 збігів»).
* Переведіть і текст сторінки, і запит користувача в нижній регістр (`.lower()`), щоб пошук не залежав від великих чи малих літер:
```python
return text.lower().count(query.lower())

```




4. **Пошук по всіх сайтах та ранжування (`search(self, urls, query)`):**
* Пройдіться циклом по списку `urls`, для кожного викличте `count_matches(url, query)`.
* Зберіть результати у список кортежів `[(url, count), ...]`.
* Відсортуйте список за кількістю збігів від більшого до меншого:
```python
results.sort(key=lambda item: item[1], reverse=True)

```


* Поверніть відсортований список інтерфейсу.

### Модуль 3: `ui.py` — Графічний інтерфейс користувача (`tkinter`)

**Інструмент:** вбудована бібліотека `tkinter` (входить до Python, не потребує встановлення) та модуль діалогових вікон `from tkinter import messagebox`.

**За що відповідає клас `SearchAppUI`:**
Створює вікно програми, розміщує елементи керування, перевіряє введені користувачем дані та виводить результати.

#### Які віджети `tkinter` використати та як їх поєднати:

1. **Головне вікно (`tk.Tk`):**
* `self.root = tk.Tk()`
* `self.root.title("Пошукова система")`
* `self.root.geometry("650x500")`


2. **Поля введення (`tk.Entry`):**
* Поле для введення нового URL (`self.url_entry`).
* Поле для введення пошукового слова/фрази (`self.search_entry`).
* *Корисні методи:* `.get()` — зчитати введений текст; `.delete(0, tk.END)` — очистити поле після натискання кнопки.


3. **Кнопки (`tk.Button`):**
* **«Додати сайт»** (`command=self.handle_add_url`) — бере текст із `url_entry`, перевіряє, чи починається він із `"http://"` або `"https://"`, викликає `self.db.add_url(url)` та оновлює список сайтів.
* **«Показати збережені сайти»** (`command=self.handle_show_sites`) — викликає `self.db.get_all_urls()` і виводить список посилань у вікно результатів.
* **«Очистити БД»** (`command=self.handle_clear_db`) — запитує підтвердження через `messagebox.askyesno(...)` і, якщо користувач підтвердив, викликає `self.db.clear_database()`.
* **«Знайти»** (`command=self.handle_search`) — бере текст із `search_entry`, отримує список посилань із `self.db.get_all_urls()`, передає їх у `self.parser.search(urls, query)` та виводить відсортований рейтинг.


4. **Область виведення результатів (`tk.Text` або `tk.Listbox`):**
* Багаторядкове поле `tk.Text(self.root, height=18, width=75)` зручне тим, що в нього можна виводити як список збережених сайтів, так і пронумеровані результати пошуку з кількістю збігів.
* *Корисні методи:* `self.result_box.delete("1.0", tk.END)` (очистити поле перед новим виведенням) та `self.result_box.insert(tk.END, текст)` (додати рядок).


5. **Спливаючі повідомлення (`messagebox`):**
* `messagebox.showwarning("Увага", "Введіть посилання!")` — якщо поле порожнє.
* `messagebox.showinfo("Успіх", "Сайт додано до бази!")` — для підтвердження дії.
* `messagebox.showerror("Помилка", "Некоректне посилання")` — якщо URL не починається з `http`.


6. **Запуск головного циклу вікна (`start(self)`):**
* Метод викликає `self.root.mainloop()`, який утримує вікно відкритим і реагує на натискання кнопок.



> **Важлива порада для `tkinter`:** під час пошуку по кількох сайтах програма на кілька секунд завантажує сторінки. Щоб користувач бачив, що програма працює, а не зависла, перед запуском парсингу виведіть у поле результатів повідомлення `"Йде пошук, зачекайте..."` та викличте `self.root.update()`, щоб вікно миттєво перемалювало текст.

## 5. Типові помилки та як їх уникнути (Чек-лист перед здачею)

* **Помилка 1: Увесь код написано в одному класі або без класів взагалі.**
* *Рішення:* суворо розділіть `DatabaseManager`, `WebParser` та `SearchAppUI`. Клас БД не повинен імпортувати `tkinter` чи `requests`.


* **Помилка 2: Посилання без протоколу (`google.com` замість `https://google.com`).**
* *Рішення:* `requests.get("google.com")` викличе помилку `MissingSchema`. У методі додавання URL перевіряйте: якщо рядок не починається з `http://` або `https://`, автоматично додавайте `"https://"` на початок або показуйте попередження.


* **Помилка 3: Підрахунок слів у «сирому» HTML (`response.text`).**
* *Рішення:* якщо шукати слово `"div"`, `"class"` або `"script"` у `response.text`, парсер знайде сотні технічних тегів. Завжди використовуйте `BeautifulSoup` і метод `.get_text()`.


* **Помилка 4: Залежність від регістру літер.**
* *Рішення:* слова `"Python"`, `"python"` та `"PYTHON"` мають рахуватися разом. Завжди приводьте обидва рядки до `.lower()`.


* **Помилка 5: Програма «падає» при натисканні кнопки з порожнім полем або при порожній БД.**
* *Рішення:* перед пошуком перевіряйте `if not query.strip():` та `if not urls:`, виводячи зрозумілу підказку користувачу.
